# 04 AI 辅助内容、人工操作与验证

本说明依据项目执行记录整理，不将 AI 生成内容表述为候选人完全手写的成果。

## 1. AI 辅助范围

ChatGPT/Codex（桌面端和 VS Code）参与了方案整理、需求与契约文档、代码骨架、Pydantic 模型、合成数据、三个工具、Qwen 客户端、Agent 循环、CLI、导出、测试与文档收尾。
AI 还协助分析环境迁移、中文查询未命中、事实原文范围不符、模型预算不足和错误 Trace 缺项，并通过本地工具执行验证。
辅助模型随客户端轮次设置变化，未保存每轮精确版本，不编造固定辅助模型版本。

项目运行时模型与编程助手分开：真实验收使用阿里云 qwen-plus；离线测试和故障注入使用显式标记的受控响应替身。

## 2. 会话可证的人工决策与操作

- 候选人确认了第 4 题短视频脚本方向、Qwen、CLI、合成素材、单 Agent、本地 JSON、Python 3.11 和不开发前端/云部署的范围。
- 候选人指定 D 盘项目路径，要求不复用或修改 voicetalk、TaskForge。
- 候选人手动迁移工程，在 VS Code 打开工作区、处理项目界面操作，并持续提供实际终端与执行截图。
- 候选人在百炼创建 API Key 并本地配置，提出必须做真实模型验收和收敛到小型 MVP 的要求。
- 候选人根据题目截图纠正了 GitHub 交付形式，确认账号候选为 XCC306 并授权公开仓库交付。

现有记录未证明候选人逐行业务源码的手工修改，因此不声称“本人独立手写全部 Agent”。主要代码和文档由 AI 辅助生成与修正；具体人工主导的是范围、选择、环境操作和验收决策。

## 3. 验证职责与可检查材料

测试和 CLI 由 AI 通过本地工具实际执行，真实运行证据保存在 examples。候选人查看并转发过执行结果，要求对失败原因进行核实。自动测试通过不等于已完成人工逐行代码审查。
两个真实 Qwen 场景与第三组离线故障注入分别标记，详见 [评估文档](03-evaluation.md)。对密钥只做本地配置与排除检查，不把真实值写入仓库或说明。

提交前，候选人应通读并能解释以下关键点：模型如何选择工具、错误如何反馈、为什么草稿改动后检查失效、如何区分真实和替身证据、已知事实检查边界。尚未核实的个人审阅不写成已完成。
