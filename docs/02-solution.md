# 02 系统方案

GitHub 提交版仅补齐失败 ToolResult 的结构化 Trace，新增三组材料索引与离线工具故障演示；不改变模型自主决策或同一草稿验收门槛。当前实现和验证见 [评估](03-evaluation.md)。

版本：0.1；日期：2026-10-30；状态：初始化设计基线，保留历史描述。当前实现与真实验证见 [README](../README.md) 和 [验收记录](04-acceptance.md)；下表“本次状态”指初始化时点，并非当前缺项。

本次不依赖任何供应商 SDK，不将设计协议误写成已验证的 API 用法。

## 2. 模型驱动的执行循环

1. CLI 校验 `UserRequest`，加载可信的素材库和规则集快照，并建立 run_id。
2. 适配器把请求、事实边界、预算和三个工具的函数描述提交给 Qwen。
3. 若模型返回工具调用，控制器保存真实 tool_call_id，校验白名单与参数，再执行实际本地工具。
4. 将每条 `ToolResult` 与对应 call_id 回传模型；可检索、修改草稿、再次检查或请求补充。
5. 若模型提出完成，控制器检查最新 draft_id 对应的两项通过结果及事实覆盖；不满足则拒绝成功状态，把缺失条件反馈给模型。
6. 达到终态、预算或不可恢复错误后，落盘脱敏结果与 Trace。

模型发出的多条调用按返回顺序串行执行，便于预算和 Trace 复现。
未知工具名/非法参数不执行，生成对应失败结果回传；达到预算后停止执行剩余调用并记录 limit_reached。
控制器限制和最终验收门槛是确定性约束；不通过固定工具序列伪造自主规划。
模型返回非法草稿只允许在预算内修正；不自动补造缺失事实或把解析失败当成空脚本。

## 3. 草稿和检查结果绑定

`draft_id` 是不可变草稿快照标识；每次修改（标题、分镜、旁白、引用等）必须分配新值。
控制器在同一 run 内保存 draft_id 与规范化内容指纹的映射；禁止同 ID 不同内容，冲突为 INVALID_ARGUMENT。
这是待实现的跨调用验证，JSON Schema 本身无法保证。
两项工具返回其检查的 draft_id；每次模型编辑后，旧结果失效。
时长工具输出只是测量值；若将估计值写回草稿，也形成新快照，完成前仍须检查最终快照。
建议先保留原草稿不变，将估计信息保存在运行结果中，导出时合并展示。

## 4. 三个工具的实现计划

### search_materials

读取已校验的合成素材快照，在指定 product_id 内按 query 与 tags 字面匹配。
首版计划采用固定分词/关键词规则，按相关度降序，分数相同时按 material_id 排序，确保可复现。
没有结果返回 ok=true、空数组，而非异常；文件缺失或格式不合法是工具错误。
返回原子事实、适用范围与 synthetic 标识，不添加模型推测。

### estimate_duration

唯一口径见契约文档：统计旁白中的 Unicode 字母/数字字符，标点和空白不计。
每镜时长取 `max(旁白字符数 / chars_per_second, visual_hold_seconds)`；再加镜间过渡秒数。
工具计算草稿总时长及与目标时长的偏差；模型提供的 estimated_duration_seconds 不作为计算输入。
该估计是演示启发式，不代表真实配音时长；英文、数字念法、情绪和停顿等误差写入 warnings。

### check_rules

按可信规则集检查整个脚本的禁用字面表达、事实引用和 ID 关联。
产品范围必须匹配；对 facts 文本和引用片段做保守原子事实校验。
脚本中的产品相关断言需由模型逐条声明；无法用确定性方法保证召回全部遗漏事实。
对未覆盖的疑似产品事实产生 review finding，要求复核，不能输出已验证所有语义真实的结论。
首版自动规则只支持 `forbidden_phrase`、`required_phrase`、`claim_references` 三种，其他需求需明确扩展。
风格只通过用户审阅/后续模型评估辅助判断；规则工具不宣称能可靠评价任意风格。

## 5. 失败、重试与预算

所有工具采用统一 ToolResult；执行失败与业务不通过分开。
空检索、too_long、规则 finding 都是成功执行的结果，由模型决定修正方式。
INVALID_ARGUMENT、UNKNOWN_TOOL 反馈模型修正；缺文件/坏数据不盲重试。
仅 TIMEOUT、临时 IO_ERROR 可 retryable；是否重试仍受模型选择、每错误最多 2 次重试和总预算限制。
模型超时、限流或鉴权失败由适配器转为脱敏的 Trace error，不制造 ToolResult 冒充工具执行。
鉴权失败立即 failed；可恢复的模型请求失败可在预算内重试，所有尝试都计次。
本地工具同步调用不能只靠检查结束时间实现硬超时；后续需可中断执行边界或明确取消策略，本阶段不实现。
不论何种停止原因，都记录结束状态与最后一条可观察动作。

初始预算：模型请求 8 次、工具执行 12 次、总耗时 180 秒；模型/本地工具单次预算 30/5 秒。
当前实现的模型请求上限为 10，其余全局上限不变。本地工具为同步函数，未实现进程级单次硬超时；初始设计中的全部限制不应视为均已强制实现，实际边界见验收记录。
开始重试前核对剩余时间。并行调用数量也逐条计入，避免绕过工具调用上限。

## 6. 数据、配置与文件安全

素材和品牌规则分为两个 UTF-8 JSON 文档，顶层带 schema_version、dataset_id、synthetic=true。
机器可读 Schema 的 SyntheticMaterials / SyntheticRuleSet 定义布局；仅有演示例子，当前 data/ 为空。
禁止把合成材料写成小影科技产品事实；示例产品统一命名为“演示剪辑器”。
模型只提交 product_id / rule_set_id 等逻辑标识，不接受路径。
工具调用参数作为普通 JSON 验证，不 eval、不执行模型指令，不允许模型添加工具。
未来输出仅写指定输出目录，默认新 run_id 文件名；冲突时拒绝覆盖已有文件。
`.env.example` 只有空变量，`.env`、缓存和环境目录已忽略。
Trace 不保存原始 HTTP 数据、密钥、认证头或完整环境变量。

## 7. 后续验证顺序

先把文档契约实现为 Pydantic 模型，再编写合成数据和三个工具的离线 Pytest。
随后用受控响应替身验证循环、失败、预算及草稿检查失效；替身测试不能证明真实 Tool Calling。
最后在用户配置凭据后做独立真实 Qwen 联调，保留脱敏 call_id 与实际返回，并验收五类场景。
对材料不足、超限修改和规则修正路径进行观察，确认决策会随真实结果变化。
本次只验证 CLI 的 help、初始提示和未实现状态，不把它记为业务测试。

以上验证顺序为历史计划。当前已执行 14 项离线回归及真实正常生成、资料不足两个场景；初始五类场景没有全部逐项做独立真实联调，证据以 [验收记录](04-acceptance.md) 为准。
