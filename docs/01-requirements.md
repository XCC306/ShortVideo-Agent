## 1. 项目来源与目标

根据用户确认，选题为小影科技 AI Agent 笔试第 4 题短视频脚本 Agent。
当前没有笔试原题附件，本规格记录会话中确认的工程范围；不声称逐字复述官方评分细则。

用户提交主题、受众、平台、目标时长和风格，系统基于本地合成产品资料生成可追溯的短视频脚本，估算时长、检查规则，并按工具反馈自主修改。
产物是脚本，不包含视频、图片或音频生成。

## 3. 输入与输出

输入 `UserRequest` 必须包含 `schema_version`、`request_id`、`topic`、`audience`、`platform`、`target_duration_seconds`、`style`、`product_id`、`language`。
本期语言限定 `zh-CN`；目标时长范围为 5–180 秒，是项目演示范围的设计取值。
`brand_rule_set_id` 可选，省略时由本地该产品的默认规则集解析。
字段、范围和缺失语义见 `03-data-contracts.md` 和对应 Schema。
缺失必填项或非法输入时，CLI 输出字段级错误并要求补充，不猜测时长、不进入模型调用。

成功产物包括结构化 `ScriptDraft` JSON、由其渲染的 Markdown，以及 `AgentTrace` JSON。
分镜包含画面、旁白、字幕、计划停留时长、工具估计时长和事实声明引用。
产品相关事实在标题、画面描述、字幕、旁白和整体创意中均须逐条关联证据；创意表达与事实分开。
素材标注为 synthetic，不能把合成产品能力描述成小影真实产品事实。

只有同一最新草稿通过时长检查、规则检查且不存在待复核项时，运行才能标记为 completed。
其他终态为 needs_input、failed 或 limit_reached，不能把未通过的草稿冒充可交付结果。

## 4. 功能需求与验收要点

| 编号 | 要求 | 可观察证据 |
| --- | --- | --- |
| FR-01 | 校验输入；缺失值请求补充 | 字段错误、未发生模型请求 |
| FR-02 | 本地素材检索，返回素材及事实 ID | 真实 tool_call_id、参数和结果 |
| FR-03 | 生成结构化脚本，事实来源可追溯 | ScriptDraft、Claim、MaterialReference |
| FR-04 | 程序估算时长，允许模型基于反馈修改 | 超限结果、草稿版本变化、重估结果 |
| FR-05 | 检查禁用表达、引用、原子事实边界 | RuleFinding 与 scene/claim 定位 |
| FR-06 | 模型根据真实返回自主选择下一动作 | 真实 Tool Calling 轨迹，至少两种不同决策路径 |
| FR-07 | 无素材、失败、超时和步数上限有明确终态 | 不伪造成功，不编造材料 |
| FR-08 | JSON / Markdown 输出与可审计 Trace | 最新 draft_id、检查摘要、运行状态一致 |

三个工具分别为 `search_materials`、`estimate_duration`、`check_rules`。
不允许程序固定串行调用三个工具后，把流程包装成模型自主调用。
控制器可以校验、限流和拒绝不安全/无效调用；具体检索、修改与重试决策由模型作出。

## 5. 事实与规则边界

本期采用保守的合成原子事实：`Claim.text` 必须与引用素材中的 `fact_id` 对应 `text` 完全一致。
`surface_text` 表示脚本实际出现的片段，首版也必须与该原子事实完全一致；允许在前后加创意文本。
这减少自动事实核验范围，不声称能验证任意自然语言蕴含关系。
引用 ID 存在不等于事实成立；尚未覆盖的产品断言或语义疑点必须形成 review finding，阻止 completed。
品牌规则工具可以检查明确的字面规则和引用一致性；风格与语义真实性不能仅靠关键词保证。

## 6. 后续完整功能的五类验收场景

| 场景 | 预期行为 |
| --- | --- |
| 正常完成 | 检索成功，生成有依据的脚本，同一版本两项检查通过 |
| 时长超限 | 工具返回 too_long，模型压缩内容，重新估算和规则检查 |
| 资料不足 | 零结果属于成功检索；模型可改写查询，仍不足则 needs_input |
| 规则/事实不符 | 禁用词或无效证据阻止完成；修改后重新检查 |
| 异常与边界 | 缺失时长不调用模型；工具/模型失败有记录；耗尽预算停止 |

以上为初始设计的五类验收计划。当前 14 项离线测试和两个真实场景的对应证据见 [验收记录](04-acceptance.md)，不将替身测试等同于真实模型验收。
最终应保留可复现的输入、输出和脱敏 Trace，离线测试与需凭据的真实联调分开。

## 7. 非功能要求

配置、数据、模型回复均视为数据，不允许成为任意代码或文件操作指令。
工具白名单与可信路径由程序控制，模型不能指定任意文件路径、执行命令或访问网络。
初始设计预算：最多 8 次模型请求、12 次工具执行、2 次可重试失败后的重试；总墙钟预算 180 秒。
真实联调后，当前默认模型请求上限调整为 10，其余上述全局上限不变；同一最新草稿的完成门槛不变。
单次模型请求预算 30 秒，本地工具预算 5 秒；所有重试和并行调用均计入总预算。
这些均为后续控制器待实现配置，本阶段未验证 Qwen 的具体超时或 SDK 行为。
Trace 记录动作和简短可公开决策摘要，不保存隐含思维链、密钥或认证头。
